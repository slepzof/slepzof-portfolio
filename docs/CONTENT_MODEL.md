# Контент кейсов, SEO и будущая админка

Существующие кейсы пока статические. Вводится **схема данных для последующей миграции**, не включённая автоматически в продакшен.

Файл: `content/case.schema.json`.

## Поля одной страницы

`slug`, `title`, `subtitle`, `summary`, `industry`, `role`, `year`, `period`, `cover_image`, `hero_image`, `sections[]`, `seo`, `status`.

`sections[]`: блоки `intro`, `text`, `image`, `gallery`, `metric`, `quote`, `result`. Каждая запись имеет тип и содержимое. Админка сможет переставлять блоки, редактировать текст и заменять медиа без самостоятельной вёрстки.

## SEO

Каждый кейс: уникальный title, description, canonical, один семантический H1, структурированная иерархия H2/H3, alt для содержательных фото, Open Graph, sitemap и разумная Schema.org-разметка. Структурированные данные помогают поисковым системам понимать страницу, но не гарантируют позиции.

## Метрики и согласования

Не смешивать GMV с выручкой, прибыль с оборотом, MAU с общим количеством пользователей, «до/после» с причинно доказанным эффектом. Не публиковать NDA-материалы до разрешения.

## Безопасность CMS

GitHub Pages только раздаёт статику. Будущая онлайн-админка должна выполнять запись через безопасный авторизованный backend или Git-based CMS. Нельзя добавлять секреты в клиентские JS-файлы.
