# SLEPZOF · Как загружать изображения кейсов

Актуально для главной страницы, будущих 160–200 кейсов и статей. Исходные
изображения и утверждённые макеты — источник истины. Никакой автоматической
перерисовки, изменения цветовой палитры, текста или композиции.

## Предпочтительно: отправлять исходники в чат

Прикрепляйте оригинальные **PNG / JPG / WebP / SVG** как файлы, а не
скриншоты из Telegram или уменьшенные фотографии экрана. Если изображений
много, один ZIP на проект. Отправлять по **5–15 кейсов за партию** — проще
проверить порядок и не перепутать материалы.

Рекомендуемая структура ZIP:

```text
hash-hedge/
  cover.png                # вертикальная карточка, если нужна
  hero.png                 # обложка внутреннего кейса, если нужна
  01-dashboard.png         # скриншоты в порядке отображения
  02-terminal.png
  03-mobile.png
  captions.txt             # подписи и места размещения (по желанию)
```

В сообщении укажите название проекта, slug, год, категорию и порядок экранов.
Если материал идёт в конкретное место существующего кейса — укажите блок/секцию
по названию. Если изображение должно быть **без кадрирования**, напишите это.

### Размеры исходников

- **Карточка SLEPZOF / Featured / Beyond UI:** эталонная пропорция
  **1424 × 2048**, вертикально. Для уже утверждённых обложек сохраняем исходник
  без изменений. Если обложка в другой пропорции, сначала решаем компоновку,
  а не обрезаем автоматически.
- **Большой экран внутри кейса:** присылайте полный оригинал Figma/PNG
  (например, 1440–2560 px по ширине). Пережимать вручную не нужно.
- **Мобильные экраны и галереи:** оригинальное соотношение сторон,
  без рамок или мокапов, если их нет в референсе.
- **Логотипы и иконки:** SVG предпочтительнее для простых векторных элементов.
  Сохраняйте корректные права на медиа и не добавляйте водяные знаки.

Не пересылайте изображения через мессенджер с автоматическим сжатием. JPG можно
использовать для фотографий, PNG — для UI с тонкими линиями и мелким текстом.
WebP тоже принимается как исходник.

## Если загружаете прямо в GitHub

Рабочая ветка: `dev`. Каталог исходных изображений нового кейса:

```text
assets/cases/<slug>/
  cover.png
  hero.png
  01-overview.png
  02-mobile.png
  03-checkout.png
```

Для статей:

```text
assets/articles/<slug>/
  hero.jpg
  01-figure.png
  02-diagram.png
```

**Важно:** `cases/<slug>/` — это HTML-страница, а
`assets/cases/<slug>/` — файлы изображений. Они не взаимозаменяемы.

При сборке GitHub Pages `scripts/optimize_media.py` автоматически создаёт
WebP-версии с SHA в имени, корректный `srcset`, размеры изображений и
`loading="lazy"` для следующих скриншотов. Исходный файл остаётся в GitHub
неизменённым, производные появляются только в публичном `dist`.

Механизм уже обрабатывает обложки с классом `sx25b3-art`, а также
локальные `<img>` с изображениями из `assets/cases/` и `assets/articles/`.
Он **не создаёт автоматически страницу кейса из одних изображений**:
нужны структура страницы, текст и порядок секций. Для динамически добавляемого
через CMS содержимого пути и набор размеров ещё требуется подключать через
общий рендерер.

## Какая информация нужна вместе с файлами

Достаточно одной короткой записи:

```text
Проект: Hash Hedge
Slug: hash-hedge
Год: 2026
Тип: Fintech
Изображения: cover.png — карточка; hero.png — первый экран;
01-dashboard.png — секция "Дашборд";
02-terminal.png — секция "Торговый терминал".
Ограничения: не обрезать, сохранять цвета и типографику.
```

Числовые результаты, подписи и кейс-стори не выдумываются из изображений:
передавайте их текстом или отмечайте, что используем уже утверждённые.

## Как проверять

После публикации: открыть главную и кейс на ПК и iPhone, прокрутить быстро до
избранных, проверить все обложки, качество мелкого текста и отсутствие скачков.
Исходники не удаляются. Если WebP стал заметно хуже, конкретную картинку
можно исключить из автоматической оптимизации либо увеличить качество.
